# 表示レイアウトの実測

`tests/layout-report.js` を使う。**使い捨ての計測スクリプトを書かない。**

## 何をするものか

`tests/helpers/viewports.js` の `SIZES`（実機に多い比率と、過去に不具合が出た比率）
すべてでゲームを開き、次を測って表にする。

- ステータス欄の幅・高さと、画面に占める割合
- 宇宙域（キャンバス）の幅
- **宇宙域の大きさを決めているのがパネル幅か画面高か** — ここが肝心。
  横画面のキャンバスは正方形で `min(画面幅 - パネル幅, 画面高)` に収まるので、
  パネルを細くして効くのは「パネル幅」と出ている画面だけ
- ステータス欄で**折り返している行**（折り返すとラベルと数値が泣き別れる）
- 横スクロールの発生

シナリオテストと同じ手順（`openGame` で乱数を固定し、`fillLog` でログを満たす）
で開くため、スクリーンショットを並べて比べられる。

## 使い方

```bash
cd tests

# いまの状態を測る（layout-report/ に表・JSON・スクリーンショット）
node layout-report.js

# 変更前を控えてから index.html を編集し、あとで比べる
node layout-report.js --out before
#   … index.html を編集 …
node layout-report.js --compare before/report.json
```

変わった値だけ `320 → 268 (-52)` の形で出る。変わらなかった値は数字のまま。

オプション:

| | |
|---|---|
| `--out <dir>` | 出力先（既定 `layout-report/`） |
| `--compare <json>` | 以前の `report.json` と比べて増減を出す |
| `--only <文字列>` | ラベルかサイズで絞る（`--only 横`、`--only 640x360`） |
| `--no-shots` | スクリーンショットを撮らない（速い） |

配信サーバは自動で用意する。`python3 -m http.server 8765` が既に動いていれば
それを使い、なければ起こして終了時に落とす。

## 読み方

- **「制約」が「パネル幅」** の画面は、パネルを細くすれば宇宙域が広がる。
  「画面高」なら、パネルをいくら細くしても宇宙域は変わらない
- **「折返し」が出たら幅が足りない。** `conductor/product-guidelines.md` は
  「読めることが幅の圧縮より優先する」と定めている。宇宙域を広げたいからと
  いって、折り返すところまで詰めてはいけない
- **「横スクロール」は常に不具合。** 出たら必ず直す

## 注意

- これは**測るだけ**で、合否は判定しない。壊れていないことの確認は
  `npx playwright test layout` が担う。**両方を通すこと**
- 出力先ディレクトリは `.gitignore` に入れてある。コミットしない
- 画面サイズを増減するときは `tests/helpers/viewports.js` を直す。
  シナリオテストと共用なので、両方に反映される
