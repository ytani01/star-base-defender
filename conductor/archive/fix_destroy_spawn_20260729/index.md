# Track: 敵の撃破に伴う増援を、撃った相手によらず出す

敵艦が撃破されたら新たな敵が1隻現れる、という規則がプレイヤーの攻撃にしか
効いていない。連邦艦が撃破したとき、および敵が誤射で別の敵を撃破したときは
敵が減ったままになる。すべての撃破経路から同じ処理を通す。

- [Spec](./spec.md) — 何を実現するか、何をやらないか
- [Plan](./plan.md) — フェーズ分けしたタスクリスト（進捗の唯一の正）

## なぜやるか

[Product Guide](../../product.md) は「敵艦を撃破すると敵意を煽って増援を呼び」と定めている。
**破壊が割に合わないこと**がこのゲームの中核ルールで、増援はその担保の一つ。

いま増援を出しているのは `EnemyShip.onInteract()` の1箇所だけで、
`FederationShip.onAfterAttack()` は敵を配列から取り除くだけになっている。
そのため **連邦艦に任せて敵を削らせるのが最も有利** という、
設計意図と正反対の攻略法が成立している。減点は `takeDamage()` 側にあるため
誰が撃っても効くが、増援だけが抜けている。

## 決めたこと

| | |
|---|---|
| すべての撃破経路に適用する | プレイヤー・連邦艦・敵の誤射。誰の手でも規則が一貫する |
| 撃破の後処理は1箇所にまとめる | 経路が増えても抜けが起きないようにする |
| 撤退では増援を出さない | 追い返すことが勝利条件。撃破との差がゲームの根幹 |
| 士気（spirit）は今回扱わない | バランスに直結するため別途。文書との乖離は `docs/TBD.md` に残す |

## 影響の範囲

**ゲームバランスが変わる。** 連邦艦が撃破するたびに敵が補充されるため、
味方任せの戦い方が今より不利になる。挙動を変えない前提の突き合わせ
（`regression`）は「一致しない」のが正しく、
差が撃破後の敵数だけであることを読む形になる。

同じ形の見落としが [feat_friendly_fire_20260729](../feat_friendly_fire_20260729/index.md)
でも起きている。**プレイヤーの攻撃（`EnemyShip.onInteract()`）と
NPC の攻撃（`SpaceShip.attack()`）で経路が分かれている**ことが原因で、
片方だけ直すと再発する。
