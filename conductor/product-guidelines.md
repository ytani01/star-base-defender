# プロダクトガイドライン (Product Guidelines)

[Product Guide](./product.md) が「何を作るか」を定めるのに対し、本書は「どう見せ、どう触らせるか」を定めます。
迷ったときは **「戦略的思考を妨げないこと」** を判断基準にしてください。

## デザイン原則 (Design Principles)

### レトロ SF スタイル

暗い宇宙空間を背景に、ネオンカラーの細い線で情報を描く CRT ターミナル風の見た目を基調とします。

- **色は意味を持たせる。** 装飾のために色を増やさない。
  - シアン系 = 自軍・自機・味方・基地・通常の情報
  - 黄 = 警告・注意（残量低下、コース変更、増援の検知）
  - 赤 = 危険・致命（残量30%未満、撃破、崩壊）
  - 緑 = 良好・安全
  - オレンジ／マゼンタ系 = 敵
- **色名を直接書かず、意味のある変数（CSS カスタムプロパティ）を使う。** 現在は `--color-primary` / `--color-accent` / `--color-bg-dark` を定義済み。新しい色を足す前に、既存の意味で表現できないか検討する。
- 塗りつぶしより**輪郭線**を優先する。宇宙空間の暗さを潰さない。

### ミニマリズムと明確性

- 画面上の常時表示は「ターン・スコア・自機シールド・自機エネルギー・基地シールド・彼我の艦数・ログ」に限る。これ以上増やす場合は、何を削るかを同時に決める。
- **数値は必ず量として同時に示す。** 数字だけ、バーだけ、のどちらにもしない（現在はゲージ＋数値の併記）。
- 危険な状態は、色の変化で**一目でわかる**ようにする。数値を読んで初めて気づく設計にしない。
- 宇宙域（キャンバス）は常に正方形を保ち、見切れや間延びを起こさせない。**ゲーム画面の面積を削る UI 要素を足さない。**

## ユーザーエクスペリエンス (UX Principles)

### 操作は1種類だけ

- **クリック（タップ）のみで全ての操作が完結する。** キーボードやドラッグを必須にしない。
- 「何をクリックしたか」で行動が決まる。モード切り替えや行動選択メニューを作らない。
- 取り返しのつかない操作（ドッキングなど）は、意図しない発動を防ぐため**明示的な操作を1段はさむ**。

### テンポを落とさない

- プレイヤーの操作から敵の行動完了までを、待たされたと感じない長さに収める。
- 演出（ビーム・移動）は情報を伝えるためのものであり、テンポより優先しない。
- 敵の行動にわずかな時間差をつけ、同時にワープしたような不自然さを避ける。

### モバイルを一級市民として扱う

スマートフォンでの縦持ち・横持ちの両方を、片方の劣化版にしない。

- **タップ対象は最低 48px 四方を確保する。** ただし小さい画面では宇宙域を圧迫しないよう、viewport 幅に応じて縮小する（下限は 48px）。
- 縦画面ではステータス欄を上部に、横画面ではサイドパネルに置く。**縦画面でステータス欄が宇宙域を圧迫してはならない。**
- **横画面でも同じ。** サイドパネルの幅はそのまま宇宙域の幅を削るので、固定幅にせず中身が必要とする分まで詰める。
  ただし**読めることが幅の圧縮より優先する**。行が折り返してラベルと数値が泣き別れるくらいなら、パネルは太いままでよい。
- ブラウザのツールバーの表示／非表示で高さが変わることを前提にする（`dvh` を使い、`vh` はフォールバックとして残す）。
- 文字サイズは画面幅に追従させ、拡大操作なしで読める大きさを保つ。
- 誤操作を招くため、ピンチズームやダブルタップズームは無効にする（ズームは専用ボタンで提供する）。

### 情報は流さず残す

- 戦況の報告はログとして蓄積し、さかのぼって読めるようにする。一定行数を超えたら古いものから捨てる。
- 重要な報告ほど強い色で示し、平常時の報告に埋もれさせない。

## ライティングとトーン (Writing and Tone)

### 宇宙艦隊スタイル

UI とシステムメッセージは、艦橋で交わされる交信のような、専門的かつ毅然とした文体を用います。
**特定の SF 作品の固有名詞・キャラクター名は使用しません。**

### 発信者を必ず名乗らせる

すべてのログは「誰からの報告か」を伴います。担当を混同しないでください。

| 発信者 | 担当する報告 |
|---|---|
| 操舵手 | 移動・進路・コース変更 |
| 戦術士官 | 攻撃・射程・敵の検知 |
| 機関部 | エネルギー・自機シールド |
| 通信士 | 味方（連邦艦）に関する報告 |
| 副長 | 戦況全体の要約 |
| 基地 | 基地からの通信・ドッキング |
| 司令部 | ミッションの成否 |
| コンピュータ | 自動的な状況判定・緊急時の宣告 |

### 文体のルール

- **簡潔な報告体で書く。** 一報告一文を基本とし、説明的な長文にしない。
- 状況の深刻さを文体に反映させる。平時は事実の報告、危機には呼びかけを含める。
  - 例（平時）: 「進路上に障害物。安全距離にて停止。」
  - 例（危機）: 「艦長！シールド 25% 危険です！」
- **プレイヤーを「艦長」と呼ぶ。** 「あなた」「ユーザー」とは呼ばない。
- 数値を報告する際は単位や割合を添え、裸の数字を投げない。
- 操作方法の指示ではなく、状況の報告として書く。
  （×「基地をクリックしてください」 ○「ドッキング準備完了。指示を待つ。」）
