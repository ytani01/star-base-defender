# テクノロジースタック (Tech Stack)

## 構成

| 分類 | 採用技術 | 備考 |
|---|---|---|
| 言語 | HTML / CSS / JavaScript (ES2022, Vanilla) | トランスパイルなし。ブラウザがそのまま実行する |
| ゲームエンジン | [Phaser 3](https://phaser.io/) 3.60.0 | jsDelivr の CDN から読み込み |
| 画像アセット | なし | 全てのスプライトを Phaser の Graphics API で実行時に生成 |
| 効果音 | Web Audio API | オシレータで合成。音声ファイルは持たない |
| 永続化 | `localStorage` | ハイスコアのみ。サーバ通信は一切行わない |
| ビルド | なし | `index.html` をブラウザで開けば動く |
| 依存管理 | ゲーム本体はなし | `index.html` は外部パッケージに依存しない。テスト用に `tests/package.json` のみ存在する（開発時だけ・公開物には含まれない） |
| ホスティング | GitHub Pages | `master` ブランチの内容がそのまま公開される |

## 単一ファイル構成

**ゲームの全て（HTML・CSS・JavaScript）が `index.html` 1ファイルに収まっています。**
これは暫定措置ではなく、意図的な選択です。

**採用理由:**
- ビルド工程が存在しないため、編集して保存すれば即座に結果を確認できる。
- GitHub Pages にそのまま置ける。デプロイ手順が「push するだけ」になる。
- ファイルを1つダウンロードすれば、オフラインでも（CDN 分を除き）動く。

**受け入れているコスト:**
- ファイルが大きくなる（2026-07-28 時点で約 2,600 行）。
- モジュール分割ができず、`import` / `export` が使えない。
- ユニットテストを書く土台がない（後述）。

**この方針を変えるとき:** 分割やビルドの導入を検討する場合は、実装に着手する前に本書を更新し、
「なぜ単一ファイルでは立ち行かなくなったのか」を日付付きで記録してください。

## 外部依存

依存は Phaser 3 ただ1つです。**新しいライブラリを追加しないでください。**
UI ライブラリ、ユーティリティ、フォント、アイコンセットのいずれも、現状では不要と判断しています。
追加が必要になった場合も、本書を先に更新してから実装します。

Phaser は CDN から読み込んでおり、**バージョンを URL で固定しています**（`phaser@3.60.0`）。
`latest` などの可変指定は使いません。外部の更新で突然壊れることを防ぐためです。

## Phaser の使い方

- **シーンは1つだけ。** `preload` / `create` / `update` の3関数で完結させています。
  ミッションの切り替えや再開は `scene.restart()` で行います。
- `preload()` の中で全スプライトを Graphics API から生成し、`generateTexture()` でテクスチャ化します。
  外部画像を追加しないでください。図形で描けるものだけをアセットにします。
- ターンの進行は Phaser の `time.delayedCall()` と `tweens` に乗せています。
  `setTimeout` / `setInterval` を新たに使わないでください（シーン再起動時に止められないため）。
- キャンバスのスケーリングは `Phaser.Scale.FIT` を使い、常に正方形を保ちます。

## データの永続化

- 保存するのはハイスコアのみです（キー: `starbaseDefenderScores`、上位5件）。
- **読み込みは必ず失敗を想定します。** `localStorage` が無効・破損していてもゲームは起動しなければなりません。
- 個人を特定できる情報は保存しません。ユーザー名の入力欄も設けません。

## 対応環境

- モダンブラウザの最新版（Chrome / Firefox / Safari / Edge）。
- **スマートフォンは一級市民です。** 縦持ち・横持ちの両方で成立させます（[Product Guidelines](./product-guidelines.md) 参照）。
- レガシーブラウザ向けのポリフィルは入れません。ただし `dvh` のようにサポートが割れている CSS 機能は、
  `vh` のフォールバックを併記する方針です。

## テストと静的解析

自動テストを**2層**で持ちます（2026-07-28 決定）。リンタ・型チェックは引き続き導入しません。

| 層 | 置き場所 | 依存 | 対象 |
|---|---|---|---|
| 計算のテスト | `tests.html` | なし | 純粋な計算（幾何・スコア・威力減衰） |
| シナリオテスト | `tests/` | Playwright（開発時のみ） | 操作・ターン進行・決着・レイアウト |

**この判断に至った経緯:** 本書はもともと「純粋な計算ロジックを副作用のない関数として
切り出せた段階で、その部分に限ってテストを導入する価値が生まれる」としていました。
`refactor_guidelines_20260728` の Phase 6 でその切り出しが済み、条件が満たされました。
また同 Track の Phase 5・6 では、乱数を固定して変更前後の全状態を突き合わせる方法で
「挙動を変えていない」ことを確かめており、手作業では届かない精度が出せると分かりました。

### 守るべき制約

- **ゲーム本体には何も足さない。** `index.html` は単一ファイルのままで、テストのために
  分割したり `export` を足したりしません。テスト側が `index.html` を読み込んで中の関数を
  呼びます。
- **公開されるものは増やさない。** `tests.html` と `tests/` は GitHub Pages に置かれても
  ゲームの動作に影響しませんが、`tests/node_modules` は `.gitignore` に入れます。
- **`tests.html` は依存ゼロを保つ。** ブラウザで開くだけで結果が出ること。テスト
  フレームワークを入れないこと。
- **Playwright はシナリオ層だけの依存です。** これが動かない環境でも、`tests.html` と
  手動確認でリリース判断ができる状態を保ちます。

### シナリオテストを書くときの注意

実際に書いてみて分かった落とし穴です。

- **ヘッドレスでは描画が間引かれ、Phaser のタイマーが進まないことがある。** 実時間の
  待ちに頼らず、シーンの時計を明示的に進めるか、待機中も入力を送り続けること。
- **ブラウザが `index.html` をキャッシュする。** 読み込み URL にクエリを付けること。
- **盤面の再現には、ページのスクリプトより先に `Math.random` を差し替える必要がある。**
  起動後に差し替えて `scene.restart()` する方法では、前の世界が残って再現できません。

### 手動確認との関係

自動化しても [Workflow](./workflow.md) の確認シナリオは廃止しません。
**実機のスマートフォンでの見え方とタップ感、効果音、ブラウザ差異**は引き続き人が確かめます。

## デバッグ

`index.html` 内の `DEBUG` フラグを `true` にすると、移動計算・NPC の思考・増援判定などの
詳細ログが `debugLog()` 経由でコンソールへ出力されます。既定値は `false` です。

**`console.log()` を直接書かないでください。** 必ず `debugLog()` を使います。
